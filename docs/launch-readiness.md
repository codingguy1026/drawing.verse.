# Drawing Verse 출시 준비 체크리스트

작성 기준: 2026-10-16 · 대상 브랜치: `main`

이 문서의 체크 항목은 **검증 작업 목록**입니다. 미체크 항목을 곧바로 기능 결함으로 해석하지 마세요.

## 0. 자동 검사 기반

- [ ] GitHub Actions의 **Launch readiness checks**가 `main`에서 초록색으로 통과한다.
- [ ] `npm ci`, `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`를 통과한다.
- [ ] Next.js canary 의존성을 평가하고, 안정 버전으로 옮길지 호환성 검토 후 결정한다.
- [ ] 옛 PR(#4, #5, #20)의 구현 내용이 이미 main에 반영됐는지 확인하고 중복 반영을 피한다.

## 1. 계정과 보안 · 공개 전 필수

- [ ] 회원가입 → 이메일 확인(해당하는 경우) → 로그인 → 새로고침 → 로그아웃을 실제 브라우저에서 검증한다.
- [ ] 로그인하지 않은 사용자의 작성/수정/삭제가 차단된다.
- [ ] 프로필, 게시글, 댓글, 갤러리, 유니버스 관리 작업에서 **실제 로그인 사용자**의 권한을 검증한다.
- [ ] Supabase RLS 정책과 서비스 역할 키의 서버 전용 사용 여부를 검토한다.
- [ ] 서로 다른 2개 테스트 계정으로 다른 사용자 데이터 수정·삭제 차단을 검증한다.
- [ ] 운영 변수와 마이그레이션을 확인하고 비밀 키를 저장소 또는 브라우저에 노출하지 않는다.
- [ ] 로그인 실패, 네트워크 장애, DB 오류 때 사용자에게 읽을 수 있는 오류를 보여준다.

## 2. 핵심 사용자 여정 · 공개 전 필수

- [ ] 홈 → 유니버스 탐색 → 상세 → 글 작성 → 작성한 글 확인.
- [ ] 유니버스 생성 마법사에서 유효성 검사, 중복 slug, 소유자 지정, 생성 후 이동을 확인한다.
- [ ] 프로필 수정 → 본인 이름/프로필로 게시글과 갤러리가 표시된다. 익명 게시판 방식으로 회귀하지 않는다.
- [ ] 갤러리 업로드, 상세 조회와 본인 콘텐츠 관리가 실제 Supabase에 연동된다.
- [ ] 댓글, 팔로우, 검색, 알림 등 공개된 UI의 실제 동작을 확인한다.
- [ ] 빈 화면, 로딩, 404, 권한 없음, 오류 복구 상태가 정상 작동한다.

## 3. UI 품질 · 공개 전 필수

- [ ] 휴대전화와 데스크톱 화면에서 홈, 프로필, 상세, 유니버스 생성 페이지를 점검한다.
- [ ] 다크/라이트 모드에서 모든 버튼 글자와 배경 대비를 확인한다.
- [ ] 상단/측면 내비게이션, 뒤로 가기, 터치 대상 크기, 키보드 탐색을 점검한다.
- [ ] 더미 숫자, 가짜 사용자 목록, 미작동 버튼, 샘플 콘텐츠가 실제 데이터인 것처럼 보이지 않는지 점검한다.
- [ ] 이미지 대체 텍스트와 오류 메시지 접근성을 점검한다.

## 4. 운영 안정성 · 공개 전 필수

- [ ] Railway 배포에서 빌드, 시작, 재배포와 환경 변수 설정을 검증한다.
- [ ] 주요 API의 인증/오류 코드 및 서버 로그를 확인한다.
- [ ] 배포 실패 시 이전 버전으로 되돌리는 절차를 정한다.
- [ ] 외부 API(기상·스포츠 등)가 없어도 핵심 커뮤니티 사용이 막히지 않는다.
- [ ] 이미지 저장소 용량과 서비스 비용, 데이터 백업, 운영자 대응 방법을 확인한다.

## 5. 출시 판단

**공개 가능:** 자동 검사 통과 + 1~4의 공개 전 필수 항목 검증 + 치명적인 보안/데이터 손실 문제 없음.

**공개 보류:** 인증/권한 검증 실패, 잘못된 사용자에게 데이터 수정 권한 제공, 빌드·배포 실패, 핵심 글쓰기/유니버스 생성 실패.

## 이번 첫 변경의 범위

이 첫 변경은 테스트 명령, CI 워크플로, 개발/출시 안내만 추가합니다. **앱 로직이나 DB는 변경하지 않습니다.** 따라서 실제 배포 성공과 UI/보안 검증은 별도 결과가 필요합니다.
